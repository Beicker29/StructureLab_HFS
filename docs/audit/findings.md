Prioridad P0 = confiabilidad/seguridad primero; P1 = calidad/alcance; P2 = evolución. **Observado** significa código o ejecución verificable; **hipótesis** significa efecto físico o fidelidad normativa aún pendiente de contraste. Un defecto de software confirmado no demuestra por sí solo una capacidad estructural incorrecta en todos los casos.

## Evidencia conservada y límites de aceptación

Conservar: funciones separadas del CLI, errores estructurados, bloqueos verificables por datos insuficientes (2L/E4), restricciones de método existentes y las pruebas originales que siguen pasando. La estructura actual ofrece puntos de aislamiento útiles; no se justifica una reescritura integral a partir de este baseline.

Correcciones propuestas, no implementadas: cierre de cobertura antes de declarar PASS; validación de campos/dominios; clasificación completa de esbeltez; contrato de ejes; resultados con dimensión y precisión explícitas; rechazo o identificación de duplicados. Revisar esas decisiones con evidencia normativa cuando cambien cálculos, aplicabilidad o propiedades. Las extracciones arquitectónicas deben resolver duplicación/acoplamiento concreto y conservar la línea base revisada.

No se usaron salidas del propio motor para afirmar exactitud AISC. Las fixtures congeladas sirven para detectar cambios, incluidos cambios deseados al corregir defectos: nunca deben obligar a conservar un falso PASS. HFS-001 y todas las tareas posteriores permanecen sin ejecutar.
